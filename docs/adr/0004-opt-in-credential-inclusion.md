# 逐凭证纳入，默认不作用任何凭证

插件对凭证的作用范围从排除名单（`exclude_credentials`，默认全部生效）改为纳入名单（`include_credentials`，默认空）。理由：消耗 reset credit 是不可逆且稀缺的动作，漏配的代价不对称——opt-out 下任何一个未列出的账号都会被动消耗 credit，而 opt-in 下漏配只是"插件没帮忙"，不烧卡。默认全开等于让"配置疏漏"直接变现为不可逆损失，默认全关则把决策权交回运维。

## Considered Options

- **保留排除语义，仅换名字/默认值**：排除名单本质上要求运维穷举"不该碰"的账号，新增账号会自动落入生效范围；与"消费不可逆"冲突，排除。
- **过渡期同时兼容两个键**：两种语义共存时"未列出"的含义相反，无法解释也无法审计；且插件尚无已安装用户，没有兼容包袱，排除。

## Consequences

首次使用或升级后必须显式列出 `include_credentials`，否则插件启用却静默不动作。为消除这个静默失败，`parseConfig` 在 `enabled` 为真且名单（过滤空串后）为空时记一条 warn。
